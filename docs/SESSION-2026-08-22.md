## Architecture (current)

Streamlit (`app.py`) and CLI (`python -m scene_analysis`) share `src/scene_analysis`.

**Device:** `device.py` treats `torch.version.hip` + `torch.cuda.is_available()` as ROCm (HIP compatibility API is still `cuda:0`). Fallback: DirectML, then CPU. Native Windows has no official ROCm PyTorch wheels; GPU path is Linux/WSL2.

**Vision (local GPU/CPU):**

| Task | Model | Default |
| --- | --- | --- |
| Detect | YOLO (`yolo11n.pt` default) | On |
| Scene tags | CLIP `openai/clip-vit-base-patch32` | On |
| Caption | BLIP | Off |
| Depth | Depth Anything V2 Small | Off |
| Composition | CPU numpy (palette, sharpness, thirds) | On |

**Narrative (optional, stills only — never in the live loop):**

- Default provider: **LM Studio** at `http://localhost:1234/v1`, preferred model `qwen/qwen3.8-27b`.
- Alternate: **Grok 4.6** via `XAI_API_KEY` and `https://api.x.ai/v1` Responses API.

**Inputs:** upload image, upload video (`outputs/` on disk), live camera (host webcam/RTSP), browser camera snapshot, synthetic demo.

## Live camera

- Streamlit: **Live camera** → Start/Stop. Uses OpenCV on the **Streamlit host**, not the browser. Browser stills are **Camera snapshot**.
- YOLO every frame; CLIP/composition every N frames (default 15). Caption/depth only if “Allow caption/depth on live”. LLM narrative is never called live.
- CLI: `python -m scene_analysis --live --camera 0` (Q/Esc to quit).
- **Frames are not written to disk.** RAM only; next frame replaces the previous. Session state keeps tags, counts, FPS, frame index. Uploaded videos *are* saved under `outputs/`.

## Bugs fixed in this session

### CLIP / Transformers 5

`get_image_features` / `get_text_features` return `BaseModelOutputWithPooling`, not a tensor. Fix: `embedding_from_clip_output()` uses `.pooler_output`. `_load()` completes text embeddings even if a prior run set `_model` and then crashed. Restart Streamlit after that fix so `st.cache_resource` drops the half-loaded pipeline.

### LM Studio `fetch failed` (400)

Causes: sending a photo to a **text** model (`qwen/qwen3.8-27b`); sending a Hugging Face-style id that is **not loaded**, so LM Studio tries to download it.

Fixes:

- Narrative is **text-only by default** (Send snapshot off; CLI `--llm-image` to opt in).
- Resolve the requested id against the catalog (`match_loaded_model`).
- Clearer errors; retry without image after a short pause if an image request was attempted.

### LM Studio model list

UI dropdown lists **all downloaded LLMs**, not only the loaded one. Sources in order:

1. `GET /api/v1/models`
2. `GET /api/v0/models`
3. OpenAI `GET /v1/models`
4. `lms ls --json`

Embeddings omitted; loaded LLMs first. **Refresh model list** clears the 20s cache. If the server is down, a manual text field is shown.
